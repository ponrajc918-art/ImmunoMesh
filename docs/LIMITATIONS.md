# Limitations

- **No physical deployment.** No Raspberry Pi, managed switch, or IP camera was used anywhere.
  All flow records are synthetic, generated by `immunomesh/simulation/traffic.py`.
- **Dataset.** Traffic profiles (packet/byte rates, periods) for camera/sensor/PLC devices and
  the five attack patterns are hand-specified approximations documented in that module's
  source, not measurements from real devices; absolute numbers (e.g. simulated latency) do not
  transfer to real hardware timing.
- **Peer correlation.** Simulated peer monitors share the feature pipeline and baseline
  distribution (Phase 8 docstring), so consensus should not be read as evidence of true
  independent corroboration.
- **Brute-force / low-rate attacks are harder to detect than scans**, and detection heavily
  depends on the attacked device's own baseline traffic profile; see
  `docs/BRUTE_FORCE_INVESTIGATION.md` (data in `results/investigations/brute_force/`) for the multi-seed (100–109) investigation
  and the exact numbers behind that statement. AUC for brute force is high (~0.98) — the
  ranking is good — but recall at the fixed 0.99-quantile threshold is markedly lower for
  brute force and traffic-spike attacks against low-baseline-rate devices, because the shared,
  device-agnostic threshold is calibrated on the pooled training-score distribution.
- **False positives/negatives exist** at every intensity level and are reported, not hidden;
  see `results/final/RESULTS.md` (multi-seed) and the earlier `results/run_seed42_*` (Phase 5
  preliminary single-seed baseline).
- **Response/quarantine is a software state change only** and has not been mapped to any real
  network control.
- **Computational constraints.** Multi-seed experiments were run with 900s simulated
  train/eval periods per seed (see `results/final/run_manifest.json` for the exact seeds and
  durations actually used) rather than the full 1800s default, for tractable runtime on this
  machine; this is a scale choice, documented for reproducibility, not a change to detector or
  simulator behaviour.
- **Domain shift.** The simulator's normal/attack distributions are stationary within a run;
  no gradual drift, seasonal effects, or novel unmodelled attack types are represented.

- **Trust-only alerting trades precision for a longer memory of past suspicion.** In the
  Phase 10 ablation (`results/final/tables/ablation_E3_high_intensity.csv`), enabling trust
  (A2) drops epoch-level precision sharply versus evidence-only (A1: ~0.86 → A2: ~0.35) while
  recall stays similar. This is expected from the trust design: trust recovers geometrically
  (`lambda_rec=0.10` per clean epoch) so it stays below `alert_trust` for many epochs after a
  single attack window ends, and `alert = trust < alert_trust` keeps firing during that
  recovery tail. The full response state machine (A4) recovers some of that precision by
  alerting on discrete states (HIGH_RISK/QUARANTINED/RECOVERING) rather than a continuously
  decaying score. Whether "stay alert longer after an incident" is a feature or a cost depends
  on the deployment's tolerance for false alerts; both readings are legitimate and this trade-off
  should be tuned deliberately, not treated as a bug.

- **Per-attack recall rests on few seeds.** In each seed only a few attack windows are drawn, so an
  attack type appears in only some seeds. In E3, `n_seeds` is 6 (brute force), 6 (protocol
  irregularity), 5 (port scan) and only 4 (exfiltration and traffic spike). Exfiltration recall
  0.285 has a per-seed range 0.10-0.49; traffic-spike recall ranges 0.00-0.99 (std 0.46). These
  per-attack figures are indicative, not precise estimates. See `results/final/tables/per_attack_recall_E3.csv`.
- **Exfiltration is poorly detected by Isolation Forest at the chosen 0.99-quantile threshold.** Its
  cause has not been established. In the model comparison, One-Class SVM and Local Outlier Factor reach
  flow-level recall 0.99-1.00 in E3, which suggests (but does not show — per-attack recall was not
  computed for them) that the weakness may be specific to the Isolation Forest + threshold
  combination rather than to the 15 features. This is an open question, not a result.
- **Isolation Forest is not the best-scoring detector here.** In E3: precision 0.948 (IF) vs 0.938
  (LOF) vs 0.912 (OCSVM); recall 0.826 vs 0.992 vs 1.000; F1 0.877 vs 0.964 vs 0.954; ROC-AUC 0.989 vs
  0.998 vs 0.999. The 0.010 precision advantage of IF over LOF is smaller than its standard deviation
  (0.021). Paired per-seed differences (n=8) are consistent at high intensity — LOF has higher recall,
  F1 and ROC-AUC in 8/8 seeds, OCSVM higher recall and ROC-AUC in 8/8 and F1 in 6/8 — but at low
  intensity only recall is consistent (OCSVM 8/8, LOF 6/8), while F1 is higher in just 4-5 of 8 seeds.
  No significance test was run. All three models are fit on anomaly-free data without labels, so "unsupervised" does not
  distinguish them. The evidence layer's SHAP `TreeExplainer` is specific to tree models, so IF is the
  detector the explainability design depends on; no timing comparison is supported (IF fit time was not
  measured).
- **The evidence-corroboration component made no difference to alert decisions** in the ablation (A0
  and A1 are identical in every reported metric), because nearly every flagged flow was corroborated.
  Its contribution is explanatory output, not changed detection.
- **Trust-based variants detect fewer attack windows.** In E3, window detection rate is 0.969 for
  A0/A1/A4 but 0.875 for A2/A3, with higher latency (about 10.3-10.9 s vs 8.1 s).
- **The live runtime is narrower than the simulation.** It uses the feature pipeline, Isolation Forest,
  evidence (not persisted) and trust. Peer consensus, the response state machine and the enforcement
  executor are not wired into `monitor`/`edge`; the executor is tested only against fake adapters.
- **E1 (normal-only) has no attack flows**, so precision, recall, F1 and ROC-AUC are undefined there;
  only the false-positive rate (about 0.009) is meaningful.
- **Flow-level and epoch/window-level metrics are different quantities** and must not be compared
  directly (see the note at the top of `results/final/RESULTS.md`).

## Future work
Raspberry Pi edge deployment; real IP-camera and managed-switch telemetry; live network
capture; an actual industrial testbed; independent (non-shared-pipeline) peer sensors; mapping
quarantine states to real network controls; adversarial-robustness evaluation.
